## 〇、TL;DR

本仓库是 **F11QA 测试体系**的 ROM 长期 mirror：

- **内容**：NES 第三方测试 ROM 字节 + 元数据（LICENSES.md / SHA256SUMS / scripts）
- **不内容**：NES 模拟器引擎、测试 harness、CI workflow 与 FCEUX11 主项目耦合的部分
- **作用**：当第三方上游（个人主页 / 老论坛 / mediafire）失效时，F11QA 测试仍能从此仓库稳定拉取 ROM
- **License 政策**：仅纳入 PD / zlib / GPL 兼容 ROM；每个 ROM 单独标注
- **同步机制**：4 层防御（多源 + Wayback + 本仓库自循环 + WORM archive）

**一句话**：本仓库是 F11QA 测试 ROM 的**版权隔离 + 长期可获得性**基础设施。

## 一、目标与不目标

### 1.1 目标（DO）

| # | 目标 | 衡量 |
|---|---|---|
| 1 | 提供 F11QA 测试所需全部第三方 ROM 字节 | 与 F11QA `f11qa_license_manifest.json` 100% 覆盖 |
| 2 | 完整 license audit trail | 每个 ROM 在 `LICENSES.md` 有源 URL + license 字段 |
| 4 | 长期可获得性 | 任意上游失效 → 本仓库仍可读 |
| 5 | 防止版权污染 | 不引入任何 license 不明 / 上游不存在的 ROM |
| 6 | 独立于 FCEUX11 主项目 | 本仓库不与 FCEUX11 仓库共享任何代码或二进制 |

### 1.2 不目标（DON'T）

- ❌ **不存储 FCEUX11 引擎代码**——这是镜像，不是 fork
- ❌ **不存储 F11QA 测试 harness**——留在 FCEUX11 主项目
- ❌ **不存储闭源 / license 不明的 ROM**——宁可漏测也不引争议
- ❌ **不主动 fork / 修改 ROM 字节**——本仓库仅 1:1 镜像
- ❌ **不提供任何 NES 游戏 ROM**——本仓库**仅**测试 ROM

## 四、4 层防御：长期可获得性

### 第 1 层：每个 ROM 多源（2 源起 + Wayback fallback）

每个 ROM 的 fetch 顺序在 `scripts/sync_from_upstream.sh` 中实现：

```bash
#!/usr/bin/env bash
#伪代码
fetch_rom() {
    local rom_path="$1"
    local expected_sha256="$2"
    shift 2
    local sources=("$@")

    for src in "${sources[@]}"; do
        if download "$src" "$rom_path"; then
            actual=$(sha256sum "$rom_path" | awk '{print $1}')
            if [ "$actual" = "$expected_sha256" ]; then
                echo "OK: $src → $actual"
                return 0
            fi
        fi
    done

    # 终极 fallback: Wayback Machine
    for src in "${sources[@]}"; do
        wayback_url="https://web.archive.org/web/2024/$src"
        if download "$wayback_url" "$rom_path"; then
            actual=$(sha256sum "$rom_path" | awk '{print $1}')
            if [ "$actual" = "$expected_sha256" ]; then
                echo "OK: $wayback_url → $actual"
                return 0
            fi
        fi
    done

    echo "FAIL: all sources exhausted for $rom_path"
    return 1
}
```

### 第 2 层：每半年自动 sync（GitHub Action）

```yaml
# .github/workflows/f11qa-rom-mirror-sync.yml
name: ROM mirror sync
on:
  schedule:
    - cron: '0 2 1 1,7 *'   # 每年 1 月 1 号 + 7 月 1 号，UTC 02:00
  workflow_dispatch:

jobs:
  sync:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - name: Run sync script
        run: bash scripts/sync_from_upstream.sh
      - name: Run license verification
        run: bash scripts/verify_licenses.sh
      - name: Run SHA-256 audit
        run: bash scripts/audit_sha256.sh
      - name: Open issue if drift detected
        if: failure()
        uses: actions/github-script@v7
        with:
          script: |
            github.rest.issues.create({
              owner: context.repo.owner,
              repo: context.repo.repo,
              title: `ROM mirror drift detected at ${new Date().toISOString().split('T')[0]}`,
              body: '`sync_from_upstream.sh` 或 `verify_licenses.sh` 失败。请 maintainer 审查上游变更并决定 PR。',
              labels: ['rom-drift', 'maintainer-action-required']
            })
```

### 第 3 层：手动 immutable archive tag

由 OWNER 在需要时手动触发（GitHub Actions → Run workflow）：

```bash
git tag -a archive-$(date +%Y-%m) $(git rev-parse main)
git push origin archive-$(date +%Y-%m)
```

`git tag -a` 创建 annotated tag——永久不可变 commit pointer。即使 mirror 仓库后续被改写，archive tag 仍指向当时的完整快照。

### 第 4 层：双仓冗余（与 FCEUX11 主项目 GitHub Actions）

FCEUX11 主项目的 `scripts/download_<suite>_roms.ps1` 内置如下源链（**默认 upstream，失败后自动切换 mirror**）：

```powershell
$sources = @(
    # 主源：上游原 URL
    "https://github.com/christopherpow/nes-test-roms/raw/master/blargg/...",

    # 第 2 源：本仓库 mirror（任一上游失效时启用）
    "https://raw.githubusercontent.com/Laffinty/f11qa-rom-mirror/main/blargg/...",

    # 第 3 源：Wayback Machine
    "https://web.archive.org/web/2024/https://github.com/christopherpow/nes-test-roms/raw/master/blargg/..."
)
```

**FCEUX11 主仓库不 vendor ROM**——避免主仓库被 copyright strike。本仓库作为独立 mirror 提供 ROM 字节。

## 六、收录新 ROM 流程（OWNER 内部 checklist）

> 本节描述 OWNER **主动收录** ROM 时的内部 checklist。
> 本仓库 **不接受** 外部 PR 直接 vendor 新 ROM——见 `README.md §收录与法律声明 §2`。
> 上游作者与权利人维权流程见 `README.md §收录与法律声明 §5`。

OWNER 收录每个新 ROM 时必须满足：

- [ ] ROM 文件已 vendor 到正确子目录
- [ ] `LICENSES.md` 追加一条记录（含 license / upstream URL / author / verified-by）
- [ ] `SHA256SUMS.txt` 追加对应行
- [ ] OWNER commit message 内 **明示上游 URL + license 声明**
- [ ] 上游 license 文件已复制到本仓库对应子目录（如果是 zlib / GPL 类）
- [ ] 本地跑 `bash scripts/verify_licenses.sh` → PASS
- [ ] 本地跑 `bash scripts/audit_sha256.sh` → PASS
- [ ] CI 自动重跑通过
- [ ] OWNER 本人 review license 字段
  —— 本仓库单一 OWNER 维护，**不** 存在第三方 maintainer 介入

**任何一项缺失 → OWNER 不 push**，直到补齐为止。

## 七、CI Workflows（本仓库）

| Workflow | 触发 | 责任 |
|---|---|---|
| `f11qa-rom-mirror-sync.yml` | 每半年 cron（1/1 + 7/1）+ workflow_dispatch | 同步上游 + 校验 license + 审计 hash |
| `f11qa-rom-mirror-verify.yml` | PR + push | 仅校验 hash + license（不拉上游） |
| `f11qa-rom-mirror-archive.yml` | 手动 workflow_dispatch | 创建 archive-YYYY-MM tag |

**关键设计**：
- PR 上的 verify **不会 fetch 上游**（避免 PR fork 仓库被外部链接指向）
- semi-annual sync **由 maintainer 仓库 cron 触发**（write permission）
- manual archive **OWNER 显式触发**（保护 tag 不可变性）

## 八、与 FCEUX11 主项目（Laffinty/FCEUX11）的接口契约

| 维度 | FCEUX11 主项目 | 本仓库 |
|---|---|---|
| 内容 | 引擎 + 测试 harness + 测试 schema | 仅 ROM + license metadata |
| License | GPL-2.0 | CC0-1.0（metadata）+ 各 ROM 各自 license |
| GitHub Actions | 跑测试 / 跑 R4 gate | 跑 sync / verify / archive |
| 触发方式 | push / PR / cron | 几乎只有 PR+每半年 cron |
| 数据流 | CI 拉 ROM → 跑测试 | cron 拉上游 → vendor → 写 hash + license |

**契约**：
- 本仓库保证 `raw.githubusercontent.com/Laffinty/f11qa-rom-mirror/main/<suite>/<path>` 永久可读（即 GitHub 仓库存活）
- FCEUX11 主项目 CI 在主源失败时自动切本仓库
- 任意一端 ROM 不一致 → CI 失败 + 报警（因为 SHA-256 不匹配）

## 十、版权退出机制（Rights-Holder Takedown）

> 完整法律流程以 `README.md §收录与法律声明 §5` 为准；本节为流程速览。
> "Rights-Holder" 涵盖原作者、版权受让方、以及任何合法权利主张人，
> 不限于原作者本人。

如果某 ROM 的合法权利人要求从本仓库移除：

1. OWNER 收到 issue / email / GitHub DMCA 通知（任一渠道）
2. 24h 内确认请求者身份（GitHub 用户名匹配 / 域名 email / 上游 commit history）
3. 立即删除该 ROM 文件
4. 从 `LICENSES.md` 移除条目
5. 从 `SHA256SUMS.txt` 移除条目
6. 从 `f11qa-rom-mirror` 删除对应 git 历史
   （`git filter-branch` 或 `git filter-repo`）—— **仅在请求者强烈要求时执行**
7. 在 issue 内回复"已移除"
8. **无需问理由**——这是 OWNER 的安全底线

**保险起见**：在 `README.md §收录与法律声明 §5` 与本节内明示
"OWNER 保留无条件删除任何 ROM 的权利"。

## 十一、回归与基线

### 11.1 已知风险

| 风险 | 等级 | 缓解 |
|---|---|---|
| 上游 ROM 字节被修改（如作者重发新版）| 中 | SHA-256 校验 + 任何变动触发 issue |
| 上游 ROM 被替换（恶意 / 失误）| 低 | 多源（主源 / 本仓库 / wayback）比 hash，多数情况会立即发现 |
| 上游完全消失（个人主页下线）| 中 | 本仓库是 mirror；manual archive tag 永久保存 |
| Maintainer 不存在 / 无响应 | 中 | 本仓库 git history 不可变，archive tag 永远可读 |
| 版权争议 / DMCA | 低 | 只引入 PD / zlib / GPL ROM；takedown 流程已就绪 |

### 11.2 不向主仓库暴露风险

| 措施 | 说明 |
|---|---|
| 本仓库独立 LICENSE（CC0 metadata + 各 ROM 各自 license）| 与 FCEUX11 主仓库 GPL-2 完全隔离 |
| 本仓库 README 明示"独立 mirror，GPL-2 仅适用于主仓库" | 降低误传风险 |
| FCEUX11 主仓库 CI **不直接 vendor ROM**——仅 fetch + 缓存到 `tests/fixtures/`（gitignore）| 主仓库 git 历史不含任何 ROM 字节 |
| FCEUX11 主仓库 `LICENSES.md`（如新建）只列 ROM 来源指针，不附 ROM | 版权风险降到零 |

### 11.3 验收标准（v1.0 收口必须满足）

- [ ] `README.md`、`LICENSE`、`LICENSES.md`（含至少 22 套件 license）、`SHA256SUMS.txt` 全部就位

- [ ] GitHub Action workflow：`sync` / `verify` / `archive` 三个 yml 就绪
- [ ] 至少 blargg 套件首批 180 ROM 已 vendor + 校验通过
- [ ] LICENSES.md 每个 ROM 条目有上游 URL + 显式 license 字段
